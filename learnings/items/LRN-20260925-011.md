# 手组 dbxp 两坑：executable 改写与活跃连接阻塞

### Summary
NAS 上手组 gnu 版 `.dbxp` 时：必须把包内 `manifest.json` 的 `executable` 改写为 `bin/linux-x64/...` 形态（对齐 `dbx-plugin package` 行为），否则安装报 `backend executable does not exist`；更新被活跃连接阻塞（`blocked by active connections`）时只能 `docker restart dbx` 后重装。

### Details
- 坑 1：源码 `manifest.json` 的 `executable` 是 `bin/...` 单平台形态，官方 `package` 会按 target 改写为 `bin/linux-x64/...`。手组包若直接塞源码 manifest，包内路径（`bin/linux-x64/...`）与声明不一致，安装校验失败。解法：组包前用 python 改写再算 `checksums.json`。
- 坑 2：DBX 里有未断开的插件连接（工作台开着）时，`install` 返回 `Plugin update blocked by active connections`。无 API 可断别人建的连接，解法：`docker restart dbx`（数据卷持久化，activation 不丢），等 login 恢复后重装。`GET /api/connections` 返回的是前端 HTML，无此 API。
- 附带：NAS 旧 `target/` 是 root 产物，`rm -rf` 会 Permission denied 刷屏——改只删 `src`/`Cargo.toml`/`Cargo.lock` 后覆盖，`target` 留着给 cargo 增量复用。

### Suggested Action
发版实操顺序：编 gnu 包 → 改写 executable → 组包 →（若报 active 阻塞则 restart dbx）→ 安装 → 冒烟（connect→test→search→disconnect）。
