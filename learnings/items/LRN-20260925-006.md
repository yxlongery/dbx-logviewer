# SSH 未实现时删选项而非加依赖

### Summary
`TD-20260925-001`（SSH 模式未实现）以“移除 manifest SSH 表单字段 + 删除后端 ssh 分支”关闭，而非引入 `russh` 实现——项目零新依赖规范下，删不可用选项比加依赖更符合最小改动。

### Details
- 背景：连接表单有 `mode`（local/ssh）+ 6 个 SSH 字段，但后端 `test/connect` 遇 `mode=ssh` 直接返回可行动错误；前端 `ui/index.html` 完全不感知 mode。
- 决策：用户确认后选移除方案。删后旧连接若残留 `mode=ssh`，后端忽略该字段按本地目录处理（有单测 `connect_ignores_legacy_ssh_mode` 覆盖）。
- 改动面：`manifest.json`（删 7 个字段 + 中文定位）、`backend/src/main.rs`（删两处 ssh 分支 + 补兼容测试）、`project-knowledge` skill（删两处过时描述）、本 TD 状态 → dropped。

### Suggested Action
后续真有 SSH 需求时重开新 TD 再评估 `russh`（纯 Rust、无系统依赖）全链路实现；评估前先确认 DBX 容器侧 Secret 透传与二进制体积影响。
