# 测试包重组须改写 manifest executable 为平台路径

### Summary
工作区 `manifest.json` 的 `backend.executable` 是模板短路径（`bin/dbx-plugin-...`），官方 Release workflow 会按平台改写（`bin/linux-x64/...`）；用官方包为底重组测试包时若直接换工作区 manifest，安装报 `backend executable does not exist`，须同步改写再重算 `checksums`。

### Details
- 现象：`POST /api/plugins/install?allow_unsigned=true` 返回 `DBX-LEGACY-0001`，`detail` 找的是 `package/bin/dbx-plugin-dbx-logviewer`（无平台子目录）。
- 修复：重组时 `mf["entrypoints"]["backend"]["executable"] = "bin/linux-x64/dbx-plugin-dbx-logviewer"`（win 包对应 `bin/windows-x64/...exe`）。
- `make-test-pkg.sh` 目前只换 `ui/`（manifest 不变，无此问题）；SSH 测试包因表单字段变更必须换 manifest，踩到本坑。

### Suggested Action
含 manifest 变更的重组包一律改写 executable；后续可把该逻辑并入 `make-test-pkg.sh`。
