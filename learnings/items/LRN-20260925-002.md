# DBX 插件 Rust 开发三坑

### Summary
`dbx-plugin-sdk` 不在 crates.io（随 CLI 的 `sdk-root` 自带）；`dbx-plugin package/dev` 会自动用自带 SDK，但手跑 `cargo build/test` 需命令行 patch；`dbx-plugin dev` 只绑 loopback，跨容器 playwright 连不上。

### Details
1. 手跑 cargo 需加 `--config 'patch.crates-io.dbx-plugin-sdk.path="<全局node_modules>/@dbx-app/plugin-cli/sdk-root/plugins/sdk/rust/dbx-plugin-sdk"'`，不要改模板 `Cargo.toml`（CLI 打包自带处理）。
2. `dbx-plugin dev` 无 `--host` 参数，写死 loopback；sidecar 容器里 `ERR_CONNECTION_REFUSED` 是预期限制，只能 curl + `/api/diagnostics` 验证，点交互留桌面端。
3. Sidecar 的 `handle` 是并发执行的：实测 `tail` 紧跟 `connect` 发出会撞上“连接未建立”，前后依赖的 RPC 之间要 sleep 或等上一条返回。
4. JSON 单消息上限 8MB（SDK 常量 `MAX_JSON_BYTES`）：大文件必须分页/分块，`search` 设 `MAX_RETURN_LINES`，下载走按行分块。

### Suggested Action
写 DBX Rust 插件时照此清单先搭验证链：自检 manifest → patch 编译 → stdio 实测 RPC → package 出包 → dev 看 diagnostics。
