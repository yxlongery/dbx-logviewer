# Alpine 编的 Rust sidecar 在 Debian 容器里起不来

### Summary
Alpine 的 Rust 默认产出 musl 二进制（interpreter `/lib/ld-musl-x86_64.so.1`），放到 Debian/glibc 的 DBX 容器里报 `No such file or directory`。必须在 Debian 系环境重编 gnu 版。

### Details
- 表象：`/api/plugins/invoke` 返回 `Failed to start plugin ... No such file or directory (os error 2)`，但文件明明存在且有执行权限——这是缺动态 loader 的经典误导。
- 确诊：`file` 看 interpreter 行，musl vs `/lib64/ld-linux-x86-64.so.2` 一眼区分。
- 解法：在 NAS 上 `docker run rust:1-bookworm` 挂载源码 `cargo build --release`（SDK 用文件 patch，不改 `Cargo.toml`，见 [[LRN-20260925-002]]）。
- 两个附带坑：挂载空目录到 `/usr/local/cargo` 会盖掉镜像自带的 cargo（改挂别处 + `CARGO_HOME`）；`cargo test` 不产出可执行 bin，要再跑一遍 `cargo build`。

### Suggested Action
凡是跑在 Debian 系容器里的 Rust sidecar，一律用 `rust:*-bookworm` 构建；Alpine 本机编的只做本地逻辑验证。
