# 正式版发版排障：unix API、rerun 锁 sha、删 Release 重发

### Summary
0.1.0 发版连踩三坑：`std::os::unix::fs::symlink` 卡死 windows-x64 构建（`#[cfg]` 双分支解）；`rerun-failed-jobs` 锁定原 `head_sha`，修完推 main 后重跑仍跑旧代码；正确姿势是移 tag 到新 commit 后**删 Release 重发**，触发全新 run。

### Details
- 坑 1（代码）：`link` 的 `std::os::unix::fs::symlink` 在 Windows 报 E0433。解法：`#[cfg(unix)] let r = ...symlink` / `#[cfg(windows)] let r = ...symlink_file`，共用 `map_err`。本地 `cargo test` 7/7 只验 unix 分支，windows 分支靠 CI 验。
- 坑 2（rerun）：`rerun-failed-jobs` 复用原 run 的 `head_sha`（实测仍是旧 sha），移 tag 不影响它。且调用它需要 token 另加 `Actions: Read and write` 权限（`Contents` 不够，报 403）。
- 坑 3（重发）：`DELETE /releases/{id}` 删 Release（tag 保留在新位置）→ `POST` 同名重建 → 新 run 在新 sha 上跑。旧失败 run 留着无妨。
- 结果：新 run 5 平台全绿，Release 产出 5 个 `.dbxp` ＋ `release-candidates.json`。

### Suggested Action
发版构建失败修完后：push → 移 tag（`tag -f`＋`push -f`）→ 删 Release 重发 → 等新 run 全绿。不要指望 rerun 能拿到新代码。
