# invoke封装形参调用实参形态不一致致timeoutMs双重包装

### Summary
前端 `invoke` 封装第三形参按数字收、调用处按对象传，`timeoutMs` 被包成 `{timeoutMs: {timeoutMs: N}}`，宿主校验报 `timeoutMs must be a number`。

### Details
`ui/index.html` 中 `invoke(method, params, timeoutMs=60000)` 内部再包 `{ timeoutMs }` 发出；`logs/tail` 与 `logs/downloadChunk` 两处调用传的是 `{ timeoutMs: N }` 对象，形参收到对象后再包一层即成嵌套对象。`logs/list`/`logs/search` 走默认数字所以正常，更坐实了双重包装。
修复：签名改为 `options={timeoutMs:60000}` 并透传 `options`，调用处不变，一次修两处。

### Suggested Action
封装宿主 `invoke(method, params, options)` 时形参直接收 `options` 对象并透传，不拆包再组装；新增调用先 `grep timeoutMs` 核对三处形态一致。
