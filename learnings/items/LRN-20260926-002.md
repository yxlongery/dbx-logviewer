# 商店自动更新机制（Sync workflow + .dbx-store.json）

### Summary
商店 `Sync plugin releases to catalog PRs` workflow 每小时轮询 `automation/plugin-sources.json` 中 `autoUpdate: true` 的仓库，只认最新正式版（非 draft、非 prerelease）且带 `release-candidates.json` 资产，按 tag 取插件仓库根 `.dbx-store.json` 合并生成 candidate 并自动开 PR；自动化只开 PR，不签名不合并。

### Details
1. 注册分两处：本仓库根 `.dbx-store.json`（`metadataPath`，默认即此名）+ 商店侧 `automation/plugin-sources.json` 加 `{"repository": "yxlongery/dbx-logviewer", "metadataPath": ".dbx-store.json", "autoUpdate": true}`（独立小 PR，不碰上架 PR）。
2. `.dbx-store.json` 白名单仅 10 字段：`name/description/icon/tags/permissions/source/homepage/license/releaseNotes/localizations`，多写直接报错（`sync-release-candidate.mjs` 校验）。
3. `permissions` 即使手写也会被 Release identity 覆盖，且历史曾致 catalog/package 权限不一致被客户端拒绝更新（`io.dbx.ssh 0.7.0`、`io.dbx.files 0.1.74`），一律不手写。
4. 出现的 listing 字段即替换商店现值，省略的保留现值；`icon` 写相对路径，同步脚本按 tag 拼成 raw 链接；`source` 含 tag，每版需同步更新。
5. 文件按 tag 取：发版前先更新 `releaseNotes` 与 `source` 中 tag 再打 tag，tag 打完不动文件；已打 tag 永远读当时内容，后续改 main 不影响。
6. beta 走 prerelease 天然不触发同步；误发正式版也只是多一个 candidate PR，可手动关。

### Suggested Action
发版清单加两项：更新 `releaseNotes` + `source` tag → 打 tag；正式版放缓节奏、攒实质变更（规则见项目 AGENTS.md「商店自动更新」节）。
